# Key 周额度跟随账号重置

独立 CPR 网关插件，确认关联的 Codex 账号进入新 7 天周期后，清零 Key 的周预算
支持一个账号关联多个 Key，各 Key 独立计费与处理；首次添加关联只建立基线，不清零

仅在确认账号新周期后清零，不改变 Key 的原生到期时间，也不修改金额上限或请求路由

## 安装与使用

宿主限定官方 Codex Proxy RS v3.18.3，发行包目标平台为 Linux x86_64
插件以宿主进程身份运行，安装前应审阅源码并信任发布者

在宿主插件管理中选择 GitHub 来源 `Ming-321/CPR-key-reset-follow`，明确选择已发布标签与对应平台附件
预发行必须指定标签并允许预发行，安装前核对同名 `.sha256` 摘要
插件无必填配置，安装后打开“Key 周额度跟随账号重置”页面

1. 添加关联，按名称选择现有 Key 与 Codex 账号
2. 确认识别到账号周窗口，添加后仅保存基线
3. 正常换周自动清零，提前重置默认自动，可在工具栏关闭
4. 出现等待确认或需处理时，从横幅或对应行打开处理对话框

Key 未设置周限额时仍可关联，但清零无实际作用
关联只指定额度来源，分组与请求路由继续由宿主管理

## 异常与恢复

- 上游未返回新窗口、窗口缺失、旧样本和刷新失败均不推断换周，保留原基线
- 无法解释的边界变化等待确认，使用率下降本身不触发重置
- 重置结果未知时停止自动重试，默认保留现有用量并跳过本次
- “再清零一次”可能清掉期间新产生的消费，必须勾选确认后操作
- 暂停后恢复以当前窗口建立新基线，不补做错过的周期
- 停用或卸载插件可停止后续动作，已经执行的清零无法撤销

Key 的原生周窗口可能比账号窗口提前约 24 小时自然清零一次，这是宿主的窗口规则
上游可能直到账号首次使用后才返回新窗口，插件不会发模型请求制造窗口
